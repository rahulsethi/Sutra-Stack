# 11 · User actions

Things **only the owner** can do. An agent must not attempt these.

| # | Action | Why it is owner-only | Status |
|---|---|---|---|
| U1 | **Rotate the credentials exposed in the source vault's git history** | Sutra Core is a *fork target*. Containment is not rotation: re-tiering leaves cleartext in history, and only revoking at each provider fixes it. | ⛔ **blocks public release** |
| U2 | Decide whether the repo goes public | Currently private, deliberately, pending U1. | open |
| U3 | Install a plugin into a real harness on a clean machine | M4's verify needs a machine that did not build the code. | open |
| U4 | Find a second user and let them stand it up unaided | Gate 1. Easiest to fudge, most worth honouring. | open |
| U5 | Set an override passphrase, if the break-glass reveal is wanted | It is a secret; it must not be generated by a tool that logs. | optional |
| U6 | Choose provider keys, if prose synthesis is wanted | Sutra works without any. | optional |

## On U1

Stated at full strength because the temptation is to treat it as paperwork.

**Re-tiering is containment, not remedy.** The thirteen credential-bearing
documents in the source system were re-tiered to `local_only`, which stops them
reaching a model — and does nothing at all about the fact that the cleartext is
still in the git history of the repo Sutra was extracted from.

Publishing before rotation would propagate that exposure into the thing handed
to strangers.
