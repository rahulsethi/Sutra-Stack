Architecture — and the licence boundary

Everything outside ee/ is Apache-2.0. ee/ is commercial. The dependency arrow points one way — Core never imports from ee/ — and CI proves it on every commit by deleting the subtree and running the full suite.

One dependency

  • @sutra/core: one (gray-matter, MIT). @sutra/mcp: zero.
  • That is the auditability claim expressed as a number — the thing deciding what your AI can see is readable in an afternoon.
  • ee/src/supply/sbom.ts enforces the ceiling, so raising it is a decision rather than an accident.

Why the boundary is mechanical

  • “Core depends on ee/” discovered at release is expensive; discovered on the commit that introduces it, it is free.
  • The check stages a copy, deletes ee/, installs, builds, tests — and asserts the build emitted output, because a build that produces nothing and exits 0 looks exactly like one that worked.

Shape (c) is genuinely optional

  • The daemon and dashboard are separate packages, not a flag.
  • A flag would let the dependency creep back one import at a time, until “optional” was true only in the documentation.
